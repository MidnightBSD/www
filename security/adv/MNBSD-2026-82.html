MNBSD-2026-82: NFSv4 server remote code execution via stateid type confusion (CVE-2026-101317)

Severity: Unknown

Affected Package: kernel/nfsserver

Summary: NFSv4 server remote code execution via stateid type confusion (CVE-2026-101317)

Description

The Network File System (NFS) allows a host to export file systems so that other hosts can mount them over the network. NFS version 4 (NFSv4) servers track per-client state, such as open files, byte-range locks and delegations, each identified by a stateid. A delegation allows a client to open, lock and cache a file locally without contacting the server until the server recalls it. Clients release delegations with the DELEGRETURN operation. nfsrv_getstate() in sys/fs/nfsserver/nfs_nfsdstate.c looks up a client's state by stateid, but ignored its flags argument. When nfsrv_delegupdate() called it to process a DELEGRETURN, it returned whatever state matched the stateid, so a client could supply an open or lock stateid instead of a delegation stateid. nfsrv_delegupdate() then freed that state while it was still referenced, resulting in a use after free. A remote NFSv4 client that can open a file on an exported file system can corrupt kernel memory on the server, causing a kernel panic or potentially executing arbitrary code in the kernel. Systems not acting as NFSv4 servers are not affected. NFSv4 service is disabled by default; sysctl -n vfs.nfsd.server_max_nfsvers prints 4 when it is enabled (check the host and any vnet jail running nfsd(8)).

Affected Versions

kernel/nfsserver
