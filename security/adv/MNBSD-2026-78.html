MNBSD-2026-78: Removal of trust in emSign root certificates

Severity: Unknown

Affected Package: caroot (base system), ca_root_nss, nss

Summary: Removal of trust in emSign root certificates

Description

The base system ships a set of trusted root certificates in /usr/share/certs/trusted, generated from the Mozilla NSS root store. certctl(8) links them into /etc/ssl/certs, which base OpenSSL and the applications built on it use to verify TLS server certificates. The security/ca_root_nss mport installs the same root store as a single bundle in /usr/local/share/certs/ca-root-nss.crt, which /etc/ssl/cert.pem points to, and the security/nss mport carries it in libnssckbi.so for applications that use NSS. On 20 October 2026 Mozilla released NSS 3.131.1, which removes trust in three roots operated by emSign:

  • emSign Root CA - C1 (Mozilla bug 2083709)
  • emSign ECC Root CA - C3 (Mozilla bug 2083709)
  • emSign ECC Root CA - G3 (Mozilla bug 2084101)

According to Mozilla, the G3 removal responds to a recent security incident that affected some intermediate certificates issued under that root. Firefox clients were protected through a OneCRL update delivered on 19 October 2026; the NSS release protects consumers of the root store that do not receive revocation information or cannot block individual intermediate certificates. MidnightBSD's base system and its OpenSSL-based applications are in that position. A system that still trusts these roots accepts TLS server certificates issued under them, including certificates issued from the affected intermediates. The base system trust store has been regenerated from NSS 3.131.1 on current (master), stable/4.1 and stable/4.0. emSign Root CA - C1 and emSign ECC Root CA - C3 are removed. emSign ECC Root CA - G3 is moved to /usr/share/certs/blacklisted, so certctl(8) refuses it even when a copy is present in another trust directory. emSign Root CA - G1 is not affected and remains trusted. The regeneration also brings the base store up to date with other changes in the NSS root store since the previous update. It adds the SECOM TLS RSA and ECC Root CA 2024 and Telia RSA and EC TLS Root CA v3 roots, and stops trusting Atos TrustedRoot 2011, SecureSign Root CA12 and ePKI Root Certification Authority for TLS. security/ca_root_nss and security/nss have been updated to 3.131.1. NSS 3.131.1 requires NSPR 4.39, which devel/nspr already provides.

        Recommendations

        Upgrade the base system to a revision that includes the fix, rebuild and install world, and then remove the obsolete certificate files and rebuild the trust store links:

        cd /usr/src
make buildworld && make installworld
make delete-old
certctl rehash

        installworld rehashes the trust store before delete-old runs, so the removed emSign C1 and C3 roots remain trusted until delete-old and certctl rehash have both been run. Update the mports:

        mport update ca_root_nss
mport update nss

        As a workaround on a system that cannot be upgraded right away, copy the three certificates into the local blacklist directory and rehash. Copy the files rather than linking them, because a later base system update removes the originals.

        mkdir -p /usr/local/etc/ssl/blacklisted
cd /usr/share/certs/trusted
install -m 444 emSign_Root_CA_-_C1.pem emSign_ECC_Root_CA_-_C3.pem \
    emSign_ECC_Root_CA_-_G3.pem /usr/local/etc/ssl/blacklisted/
certctl rehash

        Do not use certctl blacklist for this on MidnightBSD 4.x: the entries it creates are discarded by the next certctl rehash, which installworld and the ca_root_nss package both run. Check the result with certctl list and certctl blacklisted. This workaround covers base OpenSSL only; applications that read /etc/ssl/cert.pem or use NSS still need the ca_root_nss and nss updates.
